# 🔔 توثيق تطبيق الباصرة (Quiz Buzzer)

توثيق كامل لتطبيق باصرة المسابقات: الفكرة، المعمارية، طريقة العمل، التشغيل، والنشر.

> ملف مختصر للبدء السريع موجود في [`README.md`](./README.md). الملف ده مرجع أشمل.

---

## 1. نظرة عامة

تطبيق **باصرة مسابقات لحظي**: المضيف ينشئ غرفة بكود، واللاعبون يدخلون من موبايلاتهم بنفس الكود.
المضيف "يجهّز الباصرة"، وأول ما اللاعبون يضغطوا، التطبيق يعرض **ترتيب الضغط (1، 2، 3...)** مع فرق التوقيت.

**أهم نقطة — العدالة:** مَن ضغط أولاً يتحدد من **ساعة السيرفر** (عمود `created_at` في قاعدة البيانات)،
مش من سرعة نت اللاعب ولا ساعة موبايله. كل ضغطة بتتسجّل كصف في جدول `buzzes` والسيرفر بيحط وقتها،
فالترتيب حيادي ومحسوم من مصدر واحد.

## 2. المميزات

| الميزة | الوصف |
|--------|-------|
| ترتيب الضغط | عرض كل اللي ضغطوا بالترتيب (1، 2، 3...) مع فرق التوقيت بالملي ثانية. |
| لوحة نقاط | المضيف يدّي/يخصم نقاط لكل لاعب، وكل لاعب يشوف نقاطه لحظياً. |
| صوت الباصرة | صوت buzzer عند الضغط (WebAudio) + نغمة تنبيه لما الباصرة تجهز. |
| اهتزاز | اهتزاز الموبايل عند الضغط (`navigator.vibrate`) لو الجهاز يدعمه. |
| عرض الأسئلة | المضيف يكتب السؤال ويظهر فوراً على شاشات كل اللاعبين. |
| أكواد سهلة | كود غرفة من 4 حروف/أرقام واضحة (بدون 0/O و 1/I الملتبسة). |
| استئناف الجلسة | لو الصفحة اتقفلت، اللاعب/المضيف يكمل غرفته تلقائياً (تخزين محلي). |
| قفل الباصرة | المضيف يقدر يقفل استقبال الضغطات بعد الجولة. |

## 3. التقنية (Tech Stack)

- **الواجهة:** HTML/CSS/JavaScript عادي — **بدون أي build step**.
- **JavaScript:** ES Modules (`import`/`export`) تُحمّل مباشرة في المتصفح.
- **الـ Backend:** [Supabase](https://supabase.com) (مشروع `marwan-buzzer`):
  - **Postgres** لتخزين الغرف واللاعبين والضغطات.
  - **Realtime (Postgres Changes)** للتزامن اللحظي بين كل الأجهزة.
- **مكتبة Supabase:** تُحمّل وقت التشغيل من `https://esm.sh/@supabase/supabase-js@2` (CDN، بدون npm).
- **الاتجاه:** عربي RTL (`<html lang="ar" dir="rtl">`).

```
│   └── styles.css      # التصميم (ثيم احتفالي، RTL، موبايل أولاً)
└── js/
    ├── config.js       # إعدادات الاتصال بـ Supabase (الرابط + المفتاح العام)
    ├── supabase.js     # تهيئة عميل Supabase
    ├── common.js       # دوال مشتركة: توليد الكود، الأصوات، الاهتزاز، helpers، تخزين محلي
    ├── host.js         # منطق المضيف: إنشاء غرفة، تجهيز/قفل، ترتيب الضغط، النقاط، الأسئلة
    └── player.js       # منطق اللاعب: انضمام بالكود، زرار الباصرة، الصوت/الاهتزاز، الترتيب والنقاط
```

### دور كل ملف JS
- **`config.js`** — `SUPABASE_URL` و `SUPABASE_KEY` (المفتاح publishable/anon، آمن في الواجهة لأن الصلاحيات محكومة بـ RLS).
- **`supabase.js`** — ينشئ عميل واحد `supabase` يُستورد في باقي الملفات.
- **`common.js`** — `generateRoomCode()`، `playBuzz()` / `playArm()` (WebAudio)، `vibrate()`، `unlockAudio()`،
  بالإضافة لـ `$()`، `escapeHtml()`، `formatDelta()` و `store` (تخزين الاسم/الكود/المعرّفات في `localStorage`).
- **`host.js`** — كل منطق المضيف (تحت).
- **`player.js`** — كل منطق اللاعب (تحت).

## 5. معمارية قاعدة البيانات

ثلاثة جداول في schema `public` (التعريف الكامل في [`schema.sql`](./schema.sql)):

### `rooms` (الغرف)
| العمود | النوع | الوصف |
|--------|-------|-------|
| `id` | uuid (PK) | معرّف الغرفة |
| `code` | text (unique) | كود الدخول (4 حروف) |
| `state` | text | حالة الباصرة: `lobby` / `armed` / `locked` |
| `round` | int | رقم الجولة الحالية (يزيد مع كل تجهيز) |
| `question` | text | نص السؤال المعروض |
| `created_at` | timestamptz | وقت الإنشاء |

### `players` (اللاعبون)
| العمود | النوع | الوصف |
|--------|-------|-------|
| `id` | uuid (PK) | معرّف اللاعب |
| `room_id` | uuid (FK → rooms) | الغرفة التابع لها |
| `name` | text | اسم اللاعب |
| `score` | int | نقاطه |
| `joined_at` | timestamptz | وقت الانضمام |

### `buzzes` (الضغطات)
| العمود | النوع | الوصف |
|--------|-------|-------|
| `id` | uuid (PK) | معرّف الضغطة |
| `room_id` | uuid (FK → rooms) | الغرفة |
| `round` | int | الجولة |
| `player_id` | uuid (FK → players) | اللاعب الضاغط |
| `created_at` | timestamptz | **وقت السيرفر = أساس الترتيب العادل** |

**قيد فريد:** `unique(room_id, round, player_id)` — يمنع اللاعب من الضغط مرتين في نفس الجولة.
**Realtime:** الجداول الثلاثة مُضافة لـ `publication supabase_realtime` مع `replica identity full`.

## 6. كيف يشتغل (التدفّق والـ Realtime)

### الدورة الكاملة
1. **إنشاء غرفة:** المضيف يضغط "أنشئ غرفة" → `INSERT` في `rooms` بكود فريد وحالة `lobby`.
2. **انضمام:** اللاعب يكتب اسمه + الكود → بحث عن الغرفة بالكود ثم `INSERT` في `players`.
   → المضيف يشوفه فوراً في لوحة النقاط (Realtime).
3. **تجهيز:** المضيف يضغط "جهّز الباصرة" → `UPDATE rooms SET state='armed', round=round+1, question=...`.
   → زرار اللاعبين يولّع وتتشغّل نغمة التنبيه.
4. **الضغط:** اللاعب يضغط → `INSERT` في `buzzes` (الوقت من السيرفر) + صوت + اهتزاز.
5. **الترتيب:** الكل يستعلم `buzzes` للجولة الحالية `ORDER BY created_at ASC` → الترتيب 1، 2، 3...
6. **النقاط:** المضيف يضغط +/- → `UPDATE players.score` → يظهر عند اللاعب لحظياً.
7. **جولة جديدة:** "جهّز الباصرة" تاني → `round` يزيد وتتصفّى الضغطات للجولة الجديدة.

### آلية الاشتراكات (Realtime)
كل عميل بيفتح **channel** لنفس الغرفة ويشترك في تغييرات Postgres مع فلترة بالـ`room_id`:

- **`host.js`** — channel `host-<roomId>`:
  - `players` (كل الأحداث، `room_id=eq.<id>`) → يحدّث لوحة النقاط وعدد اللاعبين.
  - `buzzes` (INSERT، `room_id=eq.<id>`) → يعيد استعلام ترتيب الضغط للجولة الحالية.
- **`player.js`** — channel `room-<roomId>`:
  - `rooms` (UPDATE، `id=eq.<id>`) → يستقبل الحالة/الجولة/السؤال (تجهيز، قفل، سؤال جديد).
  - `players` (UPDATE، `id=eq.<myId>`) → يحدّث نقاطه.
  - `buzzes` (INSERT، `room_id=eq.<id>`) → يعيد حساب ترتيبه في الجولة.

> الترتيب النهائي دايماً بيتقري من السيرفر (`ORDER BY created_at`)، فالعرض عند المضيف هو المرجع الرسمي.
> الضغطة المكرّرة في نفس الجولة بيرفضها القيد الفريد (كود خطأ `23505`) فالواجهة بتتجاهلها بهدوء.

## 7. دليل الاستخدام

### المضيف
1. افتح `host.html` واضغط **"أنشئ غرفة"**.
2. شارك الكود الظاهر مع اللاعبين (زر "انسخ الكود").
3. اكتب السؤال (اختياري) واضغط **"اعرض السؤال للاعبين"** أو اتركه واضغط التجهيز مباشرة.
4. اضغط **"جهّز الباصرة (جولة جديدة)"** لفتح الضغط.
5. تابع الترتيب اللحظي، وادِّ نقطة للأول من لوحة النقاط (زر **+**).
6. كرّر من الخطوة 3 لكل سؤال.

### اللاعب
1. افتح `player.html`، اكتب اسمك + كود الغرفة، واضغط **دخول**.
2. استنى لحد ما الباصرة تجهز (الزرار هيولّع ويهتز الموبايل).
3. اضغط الزرار بأسرع ما يمكن → هتسمع صوت وتشوف ترتيبك ("🥇 أنت الأول!" أو "أنت رقم #N").

```js
export const SUPABASE_URL = 'https://pkdlbrvalnjybxjsfmzd.supabase.co';
```

Supabase → SQL Editor وشغّله.

## 9. النشر (Deploy)

النشر المعتمد: **Vercel مربوط بـ GitHub** (يربط الريبو مرة واحدة، وبعدها كل push بينشر تلقائياً).

1. ادخل [vercel.com/new](https://vercel.com/new) وسجّل دخول بـ GitHub.
2. **Import** ريبو `Buzzer`. Framework Preset: **Other**. بدون Build Command. اضغط **Deploy**.
3. (مهم) Settings → Git → **Production Branch** = `claude/buzzer-app-rebuild-sd6daq` (الكود على الفرع ده).
4. الروابط الناتجة:
   - `https://<project>.vercel.app/buzzer/` — صفحة الاختيار
   - `https://<project>.vercel.app/buzzer/host.html` — المضيف
   - `https://<project>.vercel.app/buzzer/player.html` — اللاعب

الموقع static خالص، فأي استضافة static تانية (GitHub Pages مثلاً) تنفع كمان.

## 10. ملاحظات الأمان

سياسات **RLS** الحالية سمحة: دور `anon` يقدر يقرأ/يضيف/يعدّل في الجداول الثلاثة.
ده **مقبول للعبة فرح غير حساسة**، لكنه يعني نظرياً إن أي حد معاه الكود يقدر يعدّل بيانات الغرفة.

**تحسينات أمنية مقترحة لو لزم:**
- تقييد العمليات بحيث اللاعب يعدّل صفّه هو بس، والمضيف بس يعدّل الغرفة/النقاط.
- إضافة "سر مضيف" (host token) للتحكم في الغرفة.
- التحقق من الانضمام لغرفة موجودة فقط عبر سياسات أدق.

## 11. أفكار للتطوير لاحقاً

- **التصميم:** المزيد من ثيم الفرح (شعار، خطوط مخصصة).
- **قفل صارم:** إيقاف استقبال الضغطات تلقائياً بعد أول ضغطة (لوضع "أول واحد بس").
- **مؤقّت للجولة:** عدّاد تنازلي للضغط.
- **مؤثرات:** أنيميشن/كونفيتي للفائز، أصوات أغنى.
- **إدارة الغرفة:** طرد لاعب، إعادة تعيين النقاط، إنهاء اللعبة وعرض الفائز النهائي.
- **بنك أسئلة:** تحضير الأسئلة مسبقاً والتنقّل بينها.
